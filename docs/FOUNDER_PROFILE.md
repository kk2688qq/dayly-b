# 创业者画像与项目评审操作系统

本文件源自《创业项目画像-评估.MD》，用于约束案例选择和中国复刻建议。它是评估框架，不是要求机械复制某个项目。

## 创业者画像

- 个人创业者或 2–3 人小团队。
- 擅长产品设计、AI 应用开发、快速学习和验证。
- 定位于 AI 应用层，使用成熟模型 API，不研发底层模型。
- 偏好代码、自动化和异步维护；不适合重运营、地推、复杂 BD 和大团队管理。
- 启动资金为几千到几万元，可全职投入，深圳本地但产品应可远程维护。
- 目标节奏：1–2 周完成 MVP，1–3 个月看到付费信号。

## 理想项目基因

目标是面向垂直用户的 AI 微 SaaS：功能少、问题具体、持续收费、AI 是核心交付。

必须优先满足：

1. 纯数字产品，核心价值通过软件完成。
2. AI 是核心引擎，而不是营销装饰。
3. 边际成本随规模下降，主要可变成本是 API 或基础设施。
4. 用户已经在花时间或金钱解决问题，付费意愿可验证。
5. 核心交付自动化，产品可在无人值守时运行。
6. 产品有口碑、协作、输出分享或其他自生长机制。

## 不适合的项目

- 核心价值依赖人工或线下运营。
- 服务增长必须线性增加员工。
- 没有单边启动策略的双边市场。
- 依赖物业、政府或大型企业复杂合作才能启动。
- 重资产、库存、大量内容生产或人工审核。

## 成功定义

成功不是融资、估值或等待收购，而是：

- 自给自足：收入覆盖运营成本。
- 自动化运营：每日维护时间尽量低于 30 分钟。
- 自生长：新增用户中形成可观察的自然传播。
- 第一里程碑：3 个月内找到 100 个愿意付费的用户。

## 九维评分

每项 1–5 分，总分 45 分：

1. AI 依赖度
2. 产品/技术驱动程度
3. 边际成本递减
4. 低线下运营依赖
5. 付费意愿明确度
6. 自生长潜力
7. MVP 验证速度
8. 个人能力匹配度
9. 长期兴趣匹配度

判断：36–45 为绿灯；27–35 为黄灯；低于 27 为红灯。

## 一票否决

以下任一项触发，案例的中国复制结论应明确否决或重构：

1. 核心价值靠人交付，而不是软件。
2. 必须同时启动供需两端，且没有单边撬动策略。
3. 没有付费可能，只能依靠免费换规模。
4. 缺少自然传播，且增长只能长期依赖高额买量。
5. 核心瓶颈恰好是创业者短板，且无法用产品设计绕开。

## 付费验证三层

- 嘴上付费：访谈 10 个目标用户，至少 5 个明确表示愿意付费。
- 行为付费：提供真实支付入口，至少 3 人实际付款，即使金额很小。
- 持续付费：观察首月后续费，目标续费率超过 50%。

案例中的 MVP 建议必须优先验证真实付款，而不是注册、点赞或“愿意使用”。

## 标准决策流程

自我匹配 → 四问快速筛选 → 九维评分 → 检查否决项 → 写出具体付费假设 → 一周最小验证 → 继续、调整或放弃。

付费假设使用格式：我假设「某类具体用户」愿意为「明确结果」每月或每次支付「具体金额」。
