# Dayly-B 每日全球 AI 成功应用案例任务

## 目标网站

- 仓库：`kk2688qq/dayly-b`
- 网站：https://kk2688qq.github.io/dayly-b/
- 数据源：`data/cases.json`

继续使用现有页面和数据结构。不得为单个案例创建独立 HTML，不得在日常任务中重做样式。

## 任务开始时记录基线

从 `data/cases.json` 记录：

- 修改前案例总数
- 所有项目名称与 slug
- 当前最大 P 编号
- 当前根级 `updatedAt`

本次任务的预期结果必须是：案例数增加 1，新编号等于最大编号加 1。

## 选题流程

1. 从全球 AI 应用中选择一个已获得用户或商业验证的项目。
2. 排查项目名、曾用名、域名、slug 和高度相似产品，确认未收录。
3. 优先选择能提炼小团队创业方法的项目，不追逐单纯融资新闻。
4. 至少收集 3 个来源：官网/官方文档、创始人采访或公开发言，以及一个独立来源。
5. 来源冲突时保留冲突说明，不自行拼接数字。

## 案例必须回答的问题

1. 创始人是谁，过去经历如何影响选题？
2. 问题从哪里来，为什么决定创业？
3. 第一版产品是什么，花了多久和多少资源？
4. 第一批用户从哪里来？
5. 哪个事件形成第一次转折？
6. 产品如何从单点功能演进为持续工作流？
7. 增长渠道、收费方式和留存逻辑是什么？
8. 用户为什么愿意付费？
9. 竞争优势和风险边界是什么？
10. 中国团队能复制什么、不能照搬什么？
11. 最低成本 MVP 应如何验证？
12. 能沉淀出哪些可复用方法论？
13. 这个机会与 `docs/FOUNDER_PROFILE.md` 的个人创业者画像匹配吗？

## 内容完整性标准

- 至少 9 个章节。
- 创始人故事至少 3 个完整段落，并包含背景、触发事件、第一版和现实约束。
- 至少 5 个关键决策或产品阶段。
- 至少 3 个可靠来源，其中至少 1 个一手来源。
- 所有商业数字注明来源时间和口径。
- 提供明确的中国机会、风险和可执行 MVP 清单。
- 用九维评分评估中国复刻方向；触发一票否决项时明确写“不建议做”。

## 数据写入规则

- 新编号：`P` + 三位数字，严格使用当前最大编号加 1。
- `slug` 使用稳定、唯一的英文小写短横线格式。
- `publishedAt` 使用当天 `YYYY-MM-DD`。
- `status` 使用 `published`；用户已明确授权每日案例发布。
- 根级 `updatedAt` 使用当天日期。
- 新案例加入 `cases` 数组，不覆盖或删除历史案例。

## 验证与 Git 流程

1. 检查修改前后案例数，必须 `+1`。
2. 检查新编号、slug、名称和来源 URL。
3. 运行 `npm test`。
4. 检查 diff，确认未修改 HTML/CSS。
5. 提交清晰 commit，例如：`content: add P024 <project>`。
6. 推送 `main`，等待 Pages workflow 成功。

## 线上验收

使用禁止缓存的请求和真实浏览器完成：

1. 读取线上 `data/cases.json`，核对案例数、新 id、slug、章节数、来源数和 `updatedAt`。
2. 打开新案例页，核对标题、摘要、创始人故事、方法论和来源。
3. 打开首页，确认案例总数增加 1，最近发布是当天案例。
4. 检查加载状态和控制台错误。

未完成以上步骤，不得声称“网页已经更新”。
