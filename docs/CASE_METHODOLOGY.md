# 全球 AI 成功应用案例研究方法论

## 1. 成功不是融资，而是被持续使用

案例优先观察用户是否反复使用、是否付费、产品是否持续运营，以及收入能否覆盖交付成本。融资、估值和媒体报道只能作为背景。

## 2. 从创始人出发理解机会

创始人的行业经历决定他看见什么问题、拥有什么分发渠道、能承受什么风险。创业故事必须连接到产品决策，不能写成与业务无关的人物传记。

## 3. 找到最小切口

研究第一版只解决了哪一个动作，输出是否立即可验证，是否嵌入用户已有工作流。优秀切口通常具备：输入明确、输出具体、演示简单、首次价值快。

## 4. 分开研究获客与留存

免费工具、SEO、社区和演示内容可能负责获客；数据、历史记录、团队协作、自动化和业务结果才可能负责留存。不能把一次病毒传播等同于长期增长。

## 5. 还原商业化转折

重点寻找付费墙、额度、成本冲击、企业需求、渠道变化或平台扩张等转折。说明创始人做了什么取舍，以及转折如何改变收入或成本结构。

## 6. 分层表达证据

- 已验证事实：官网、产品文档、可观察页面和多来源一致信息。
- 创始人口径：采访、自述、公开帖中的收入、用户或经历。
- 编辑分析：基于事实得出的判断，必须使用“编辑判断”等提示。

## 7. 提炼方法而非复制产品

方法论应描述适用条件、机制和边界，例如“免费工具获客—付费工作流留存”，而不是简单建议“再做一个同类产品”。

## 8. 中国复制采用四步法

1. 判断本土是否存在同样频繁、昂贵的问题。
2. 找到国内软件、渠道、语言、合规与支付差异。
3. 选择一个行业和固定输入输出，设计最低成本 MVP。
4. 用连续使用和真实付费验证，而不是用注册量验证。

中国复制结论必须再通过 `docs/FOUNDER_PROFILE.md` 的九维评分和一票否决检查。全球项目成功，不代表它适合当前创业者的资源、能力和生活方式。

## 9. 付费优先于使用

不要把“愿意试用”当成需求成立。案例建议应设计三层验证：先访谈付费意愿，再提供真实支付入口，最后观察持续付费。最低成本 MVP 的目标是验证一个具体用户是否愿意为一个具体结果付钱。

## 10. 自动化和自由时间也是商业指标

评估项目时，不只观察收入规模，还要观察人工交付比例、每日维护时间、API 成本和用户自传播。一个可自动运行的小产品，可能比依赖团队和融资的大项目更符合本案例库的复刻目标。

## 11. 每篇案例的最终结构

项目基本信息 → 创始人创业故事 → 第一版产品 → 产品演进 → 关键决策 → 增长与商业模式 → 竞争与风险 → 中国复制 → 最低成本 MVP → 方法论 → 来源。
